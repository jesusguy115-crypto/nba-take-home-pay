# 托管暂扣、联盟结算与税后估值

核对日2026-10-10。薪资及赛程快照仍为2026-10-09；本季最终结算比例未知。本文件解释模型对公开条款的使用，不声称还原个人工资单。

## 默认回答的两个数字

- **主估值**：假设2026–27合同工资最终减少5.48%，先调整工资，再重新计算税额。5.48%来自2025–26报道，作为历史参照，不是新赛季预测、官方决定或置信区间。
- **合同基准**：本季最终工资扣减为零、联盟补发为零，其他条件相同，包括上季工资调整情景。这个比较只隔离本季结算影响；它不证明未来一定全额返还，也不必等于旧版本完全未调整两季工资的结果。

默认历史参数依据[报道原作者Kurt Badenhausen的说明](https://www.linkedin.com/posts/kurt-badenhausen-90bb185_nba-players-owners-to-split-580m-in-escrow-activity-7478516153640947712-jq_h)，其称2025–26结算使工资减少约5.5%；[Yahoo转载的HoopsHype报道](https://ca.sports.yahoo.com/news/total-salaries-benefits-2025-26-185256547.html)给出托管部分54.8%分配给球队。据此采用 `10% × 54.8% = 5.48%`。这是联盟报道的比例，未核验每名球员的私人调整表。

## 条款决定什么

[NBA/NBPA 2023 CBA，第VII条§12](https://imgix.cosmicjs.com/25da5eb0-15eb-11ee-b5b3-fbd321202bdf-Final-2023-NBA-Collective-Bargaining-Agreement-6-28-23.pdf)使用Designated Share结算安排。分成公式见§12(a)(15)，印刷277–278/PDF301–302：

```text
B = 实际 BRI
F = 协议定义的 Forecasted BRI
球员指定份额 D = min(0.51B, max(0.49B, 0.50F + 0.605(B−F)))
```

`F` 必须按§12(a)(17)定义取值，不是媒体预测、工资帽用的Projected BRI，也不能把公式中的 `0.50F` 改成 `0.50B`。仅有BRI仍算不出某个球员的最终扣减；需要福利、薪酬调整、结转余额等完整结算项目。模型没有用臆测的BRI反推2026–27扣减率。

球队母公司的[2026年SEC年报](https://www.sec.gov/Archives/edgar/data/1636519/000162828026056812/msgs-20260630.htm)明确说明，2023年7月起的Ten-and-Roll机制按工资暂扣10%；需回收的差额超过该比例时，可涉及福利缴款和后续赛季。CBA另规定结转利息。因此当年工资扣减上限不能宣传成跨年总损失永不超过10%，也不应把现行条款简化为已核实的第三方保险箱。

UPC §3(a)的默认24期付款从11月1日开始，每月1日及15日，延续至次年10月15日；合同可以另作安排。返还及调整依据审计与付款安排，不能写成所有球员统一在7月到账。

## 暂扣与最终扣减怎样对账

设合同薪资为 `S`，暂扣比例为 `h`，最终扣减率为 `d`，另行输入联盟补发为 `L`。以下都为税前拆解：

```text
初始暂扣 H = S × h
最终工资减少 R = S × d
初始可付工资 = S − H
暂扣返还 = max(H − R, 0)
需另补扣 = max(R − H, 0)
结算后工资 = 初始可付工资 + 暂扣返还 − 需另补扣 + L
           = S − R + L
```

例如仅作算术示范，合同1,000万美元、暂扣10%、最终减少5.48%：先暂扣100万；最终减少54.8万；暂扣中返还45.2万；结算后税前保留945.2万。应以调整后的工资重算税额，不能从全薪税后值再减100万或54.8万。

暂扣和最终减少均以Spotrac Cash Total作公开代理。它未逐份核验CBA的Adjustment Salary，签约金、保留工资、买断及特殊合同可能需要个别基数修正。另行输入的杯赛奖金不自动计入暂扣/扣减基数；不因未预测杯赛奖金而创造一笔收入。福利、联盟结转及未来工资上限影响没有折算成个人当期现金损失。

## 税务与付款年度的边界

引擎将最终保留工资视作工资收入代理，联邦、州、地方、工资税及适用抵免一起重算。上季收入代理也默认按报道比例调整，以免2026全年税率仍使用未调整的上季工资。实际税表可能涉及不同收入确认年度、调整或扣除方式；本模型没有确认W-2、实际预扣及返还时的处理，不能宣称“所有返还统一在到账时计税”或“所有被扣部分都从未计税”。

默认按原24期比例把结算后工资及联盟补发归入2026年1/6、2027年5/6，保持相同工作地点分配。这个便于比较的归属模型不证明实际退款、补发的付款时间。若提供 `annual_income_2026/2027`，数值须为已反映调整的年度工资总额；引擎不会再次缩减。

`cashflow_scenario` 只展示税前暂扣、返还、补扣、补发；实际银行到账字段为未知。不把最终年度税负当成每张工资单的预扣税，也不生成“税后数再减暂扣”的银行实收数字。经纪费如明确输入，按单独假设列示；会费与自愿退休缴款没有默认加入。

## 查询与自定义

```sh
# 默认历史参照，与申报情景一起读取缓存
python3 -X utf8 scripts/take_home.py '约基奇' --settlement historical --brief --json
# 本季没有扣减或补发的合同基准，同样快查
python3 -X utf8 scripts/take_home.py '约基奇' --settlement baseline --brief --json
# 逐项解释当前情景
python3 -X utf8 scripts/take_home.py '约基奇' --explain
```

自定义JSON通过 `--scenario` 输入：`final_reduction_rate`、`withholding_rate`、`prior_season_final_reduction_rate` 均为0至0.10之间的小数，`settlement_bonus_usd` 为非负美元。旧 `escrow_rate` 仅为暂扣比例别名；不能控制最终损失。同一输入给两个暂扣字段不同值会报错。

结果中 `spotrac_salary_usd` 为原薪资，`gross_usd` 为结算后工资加明确输入的奖金，`estimated_tax_usd` 为该情景税负，`estimated_net_usd = gross_usd − estimated_tax_usd`。`contract_baseline` 提供可比基准，`settlement_impact` 提供税前调整、税额变化及税后差额。所有真实结算状态仍由证据决定；输入一个假设比例不会把它变成官方结果。
